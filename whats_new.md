**Auto-continue now actually resumes after a usage limit.** Before, if you hit your usage limit at the same moment the server showed a temporary "Server is temporarily limiting requests (not your usage limit)" message, auto-continue trusted that "not your usage limit" wording, fast-retried a few times into the wall, and then went silent — so the chat never came back. Now, when your live usage meter confirms you're actually maxed out, it ignores that wording, waits for your limit to reset, and then resumes — which is what you wanted all along. Pure temporary server hiccups (with no real limit) still get the quick retry.

**Debug breadcrumb.** Each auto-continue decision is now recorded at `ccPatchContDbg` (per chat) so a stuck chat can be diagnosed instead of guessed at.
